# 제품 사용 가이드 텍스트 확보 — 방법과 2026-07-27 결과

MASTER_PLAN §36.5(도포량·사용 순서·사용 부위·아침저녁 구분·주의사항) 대응.
영상이 아니라 **텍스트만** 다룬다. 화면 삽입은 이 트랙 범위 밖.

## 1. 왜 새로 만들었나

사용 가이드 표시 컴포넌트(`src/components/usage/ProductUsageGuide.tsx`)는 이미
있었다. 그런데 데이터를 **`window.localStorage["skinProductUsageGuides"]`**에서
읽고 있었다. 즉 DB에 아무것도 없었고, 따라서 출처도 검수도 재확인 주기도 없었다.

이번 트랙은 그 컴포넌트가 원래 읽었어야 할 테이블을 만들고, 공식 제품
페이지에서 실제 텍스트를 채운다. **컴포넌트는 건드리지 않았다** — 여전히
localStorage를 읽는다. 배선 교체는 다음 트랙이다.

## 2. 출처 규칙

`product_offers.is_official = true`인 오퍼의 URL만 사용한다. 즉 브랜드 자사
스토어 페이지. 검색·블로그·마켓플레이스는 쓰지 않는다.

크롤링은 제품당 1페이지, 순차, 1.5초 간격. 403/429는 그대로 받아들이고 건너뛴다
— 봇 차단 우회는 프로젝트 정책상 하지 않는다.

| 명령 | 하는 일 |
|---|---|
| `npm run usage:collect-guides` | 공식 페이지 수집 + 추출 + 스냅샷 저장 |
| `npm run usage:ingest-guides` | 드라이런 (`-- --write`로 Staging 적재) |
| `npm run verify:usage-guides-staging` | 스키마 제약이 실제로 막는지 확인 |
| `npm run test:product-usage-guides` | 추출 로직 + migration 정적 검토 |

## 3. 추출은 추출만 한다

모든 필드는 **원문에 문자 그대로 있거나 null**이다. 추론·보완·의역을 하지 않는다.
지어낸 사용법은 지어낸 안전 정보이기 때문이다.

이 원칙은 관례가 아니라 **스키마 제약**이다.
`product_usage_guides_approved_requires_evidence_chk`가 사용 단계·검수 시각·출처
없이는 `approved` 상태 자체를 거부한다.

### 1차 추출이 틀렸던 4가지 (전부 테스트로 고정)

| 문제 | 증상 | 조치 |
|---|---|---|
| **EUC-KR 인코딩** | 한국 브랜드몰 상당수가 아직 EUC-KR. UTF-8로 읽으면 전부 `���`가 되는데, 추출기는 그 쓰레기에서도 "단계"를 뽑아냄 | 헤더·meta charset으로 디코딩 + `looksMojibake()` 가드. 깨진 텍스트는 절대 저장 안 됨 |
| **플레이스홀더** | `제품 상세 페이지 참조` — 안내문이지 사용법이 아님 | 플레이스홀더 패턴 목록으로 제거 |
| **구간 초과 추출** | 사용법 구간이 끝나지 않고 제조업자 블록·전성분·주의사항까지 삼킴 (`화장품 제조업자` 띄어쓰기 변형 때문) | 종료 마커를 띄어쓰기 허용으로 수정 + 주의사항 헤딩도 사용법 구간의 종료 마커로 추가 |
| **손 = 부위 오인** | `손에 덜어`(덜어내는 동작)를 사용 부위 "손"으로 기록. 얼굴 제품 대부분이 손을 부위로 갖게 됨 | 덜어내기 표현 판별 후 제외. 단 `손등`·`손에 발라`가 있으면 실제 부위로 인정 |

이 4가지를 거르자 "가이드 확보" 수치가 **55건 → 18건**으로 줄었다. 55건이 틀린
숫자였다.

## 4. 주의사항은 두 종류를 나눠 저장한다

화장품법은 모든 제품에 동일한 주의 문구(이상 증상 시 전문의 상담 / 상처 부위
사용 자제 / 어린이 손 닿지 않는 곳 보관 등)를 의무화한다. 이걸 제품별 주의사항
칸에 넣으면 **제품에 대해 아는 것보다 많이 아는 척**이 된다.

- `caution_text` — 이 제품에만 해당하는 주의사항
- `statutory_notices` — 법정 의무 문구 (검수 화면에서 별도 패널, 라벨 명시)

## 5. 2026-07-27 실행 결과

```
공식 페이지가 있는 제품            76건
실제로 가져온 페이지               70건
403/429로 차단·스로틀              6건
─────────────────────────────────────
사용 가이드 추출 성공              18건
사용법 구간이 아예 없는 페이지      52건
```

추출 성공 18건의 항목별 채움 정도:

| 항목 | 채워진 건수 |
|---|---|
| 도포량 | 10 |
| 사용 부위 | 10 |
| 아침·저녁 구분 | 6 |
| 사용 순서(원문 표현) | 5 |
| 제품별 주의사항 | 2 |
| 법정 표시 문구 | 14 |

언어: 한국어 15건, 영어 3건(글로벌 스토어). 도메인: numbuzin.com 9,
cosrx.co.kr 5, roundlab.com 3, laneige.com 1.

전부 `needs_review` 상태로만 적재된다. 승인은 `/admin/usage-guides`에서 사람이
원문과 대조한 뒤에만 가능하다.

### 왜 52건은 못 가져왔나

사용법을 **이미지로만** 넣은 상세페이지가 많다. 텍스트가 아예 없으니 추출할 게
없다. 이미지 안의 글자를 읽으려면 OCR이 필요하고, 그건 별도 판단이 필요한 작업이다.

수집 건수는 실행할 때마다 조금씩 다르다(18~21). 브랜드몰의 403/429가 그때그때
달라서다. 코드 문제가 아니다.

`products` 테이블의 **COSRX 제품명 5건이 깨져 있다** (`COSRX [ǻ�� �� ��ī ũ��
50ml]` 형태). 과거 EUC-KR 페이지에서 수집할 때 인코딩을 잘못 처리한 흔적으로
보인다. 이번 트랙에서는 **고치지 않았다** — 운영 카탈로그 데이터 수정은 별도
승인 사항이다. 사용 가이드 텍스트 자체는 이번에 디코딩을 고쳤으므로 정상이다.

## 7. 다음에 할 수 있는 것

1. **Staging 적용 후 적재** — migration 실행 → `npm run usage:ingest-guides -- --write`
2. **표시 배선 교체** — `ProductUsageGuide`가 localStorage 대신 이 테이블을 읽게.
   디자인 트랙이 `/routine`·`/results`에 도달한 뒤에 하는 게 안전하다.
3. **이미지 상세페이지 대응** — 52건을 살리려면 OCR 판단 필요.
4. **제품명 인코딩 복구** — 위 6번, 별도 승인 후.
