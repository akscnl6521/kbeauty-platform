# 159 — 국내몰 카탈로그 운영 안내서

국내 공식몰에서 제품을 가져와 추천 풀에 올리고, **낡지 않게 유지하는** 절차.
2026-08-08~10 에 만든 도구들을 언제 무엇을 위해 돌리는지 한자리에 모았다.

관련: `88-scheduled-catalog-operation.md`(자율 파이프라인 작업 — 별개다) ·
`95-catalog-quality-gates.md`

---

## 1. 주 1회 — 값이 낡지 않았는지

```
npm run check:kr-offer-freshness -- --apply
```

국내몰 페이지를 다시 받아 **가격·재고**를 저장된 값과 견주고, **화면에 나가는
사진이 아직 열리는지**도 확인한다. 몰 페이지 190여 개를 읽으므로 3~5분 걸린다.

읽는 법:

| 나오는 말 | 뜻 | 할 일 |
|---|---|---|
| `그대로` | 값이 맞다 | 없음 |
| `가격 바뀜` | 몰이 값을 바꿨다 | 자동 반영됨 |
| `품절로 바뀜` | 페이지가 품절이라고 한다 | 자동 반영됨 (구매 버튼이 사라진다) |
| `재고 표기 없음` | 몰이 재고를 안 알려준다 | **재고를 건드리지 않는다** — 추측하지 않는다 |
| `페이지를 못 받음` | 일시 장애일 수 있다 | **아무것도 안 바꾼다.** 다음 주에도 계속 나오면 그 제품을 본다 |
| `안 열림 N건` (사진) | 몰이 상품 페이지를 갈아엎었다 | 화면에서만 빠진다(지우지 않음). 다시 열리면 되살릴 수 있다 |

**왜 필요한가** — 구매 CTA 관문은 `verifiedAt` 이 **있는지**만 보고 **얼마나
오래됐는지는 보지 않는다.** 이걸 안 돌리면 2년 전 값도 그대로 «구매하기» 로 나간다.

## 2. 배포 전 — 사용자가 보는 것이 멀쩡한지

```
npm run gate:prelaunch
```

**DB 행 수가 아니라 라이브 API 응답**으로 잰다. 「이미지 84/84」 라고 보고했는데
화면에는 한 장도 안 뜬 적이 있었고(2026-08-08), DB 를 세면 그런 걸 못 잡는다.

**차단 항목**(이대로 나가면 사용자가 잘못된 것을 본다) — 하나라도 막히면 배포하지 않는다:

- 주요 화면 6종이 열린다
- 추천 풀에 제품이 있다
- **화면에 사진이 뜬다** (`http://` 0건 · 서로 다른 제품이 같은 사진 0건)

**보고 항목**(출시 기준은 사람이 정한다) — 숫자만 준다:

- 국내에서 «구매하기» 가 뜨는 제품 수
- 출처는 다른데 전성분이 같은 묶음 (용량만 다른 같은 제형일 수 있다)
- 오퍼를 마지막으로 확인한 시점

> `check:production` 은 **파일이 있는지** 보는 구조 검사다(25줄). 이름이 비슷해
> 헷갈리기 쉬운데, 그게 통과했다고 출시 준비가 된 것은 아니다.

## 3. 몰을 새로 붙일 때

### 3-1. 쓸 수 있는 몰인지 먼저 확인

```
npm run probe:kr-malls -- <도메인> [<도메인> ...]
```

다섯 가지를 본다: 사이트맵 · 제품 URL · JSON-LD 가격 · 가격이 자리표시가 아닌지 ·
**전성분이 텍스트로 있는지**.

**다섯째가 실질적인 관문이다.** 편강율은 1~4 를 다 통과하고 재고 71건을 줬는데
등록된 제품은 **0건**이었다 — 전성분을 상세 «이미지» 로만 싣기 때문이다.
활성화 게이트가 공식 전성분 텍스트를 요구하므로, 전성분이 없는 몰은 오퍼만 생기고
제품이 안 생긴다.

통과한 도메인만 `src/lib/catalog/krMalls.ts` 에 넣는다. **탈락 사유도 적어 둔다** —
같은 후보를 두 번 확인하지 않기 위해서다(지금까지 182곳 확인).

### 3-2. 수집 → 등록 → 활성화

순서대로 돌린다. 각 단계는 앞 단계가 끝나야 의미가 있다.

```
npm run snapshot:kr-malls                                   # 몰 전체 훑기 (오래 걸린다)
npm run register:kr-products                                # 먼저 dry-run 으로 목록을 눈으로 본다
npm run register:kr-products -- --apply
npm run build:ingredient-links -- --apply
npm run apply:mfds-ingredient-dictionary -- --target-production --apply
npm run apply:activate-ready -- --apply
npm run collect:images-from-offer -- --apply
npm run repair:product-categories -- --apply
```

> `--target-production` 이라는 이름을 쓰는 이유: `--production` 은 **npm 이 자기
> 설정 플래그로 먹어서** 스크립트까지 오지 않는다. 그것 때문에 아무 경고 없이
> Staging 에 96행이 들어간 적이 있다(2026-08-08).

**`register:kr-products` 의 dry-run 목록은 반드시 눈으로 본다.** 지금까지 실제로
걸러낸 것들:

- `[주주우대] … 9,900원` — 주주만 살 수 있는 값
- `[1+1]` · `(30ml/50ml/100ml)` — 그 값이 몇 개·어느 용량 것인지 알 수 없다
- 비비크림이 «토너» 로, 쿠션이 «세럼» 으로 들어옴
- **주방세제** (스킨케어 브랜드몰이 스킨케어만 팔지 않는다)
- `2종 세트` — 전성분이 **두 제품의 합**이라 안전 판정이 틀어진다

### 3-3. 활성화가 0건이면

거의 언제나 **성분 이름을 못 알아본 것**이지 성분이 없는 게 아니다. 확인 순서:

1. `npm run apply:mfds-ingredient-dictionary -- --target-production` — 식약처에 있나
2. 그래도 막히면 막은 토큰을 찍어 본다 — 지금까지 나온 것들:
   `살리실릭애씨드`(사전엔 `살리실산`) · `꿀` · `보기 정제수` · `] 정제수` ·
   `주름개선` · `장바구니 바로구매`

## 4. 데이터가 이상할 때

```
npm run check:duplicate-formulas          # 전성분이 똑같은 제품 쌍
npm run check:purchase-cta                # 구매 버튼이 안 뜨는 제품을 이름으로
npm run analyze:scenario-catalog-gap -- --target-production   # 시나리오별 준비도
```

`check:duplicate-formulas` 는 **찾아서 보여줄 뿐 고치지 않는다.** 어느 쪽이 맞는지는
`product_ingredients.source_url` 을 봐야 알 수 있고, 자동으로 정하면 멀쩡한 제품을
내리게 된다. 실제 조치는 `apply:deactivate-wrong-data` 에 **근거와 함께 이름으로**
적어 돌린다.

실제로 이렇게 잡은 것:

- «Black Snail» 인데 성분 출처가 **Advanced Snail 92 페이지**였다
- `오일 컨트롤 에센스` 와 `수분 크림` 의 전성분 39개가 **순서까지 같았다**

## 5. 운영자만 정할 수 있는 것

에이전트가 판단하지 않는다. 바꾸려면 사람이 말해야 한다.

| 무엇 | 지금 결정 | 바꾸면 |
|---|---|---|
| **재고를 안 알려주는 몰** (넘버즈인·한율·웰라쥬·일리윤·마몽드·프리메라 등, 제품 270건+) | **쓰지 않는다** | 제품이 크게 늘지만 품절 상품 «구매하기» 가 생길 수 있다 |
| 국내 구매 가능 비율을 출시 기준으로 삼을지 | 정하지 않음 (숫자만 본다) | — |
| 안전 검증기가 반려한 제품을 사람이 볼지 | 미정 | 반려는 «잘못 자르면 알레르겐이 사라진다» 를 막는 장치다 |

> 재고 판정은 **국내 오퍼 자격 조건**이라 `PROJECT_RULE`·`CLAUDE.md` 상
> 명시적 요청 없이는 바꾸지 않는다.

## 6. 보고를 믿기 전에

2026-08-08~10 사이에 **«오류는 안 나는데 아무 일도 안 일어나는»** 결함을 여섯 번 만났다.

1. `/results`·`/analyze` 에 이미지 연결이 없어 사진이 한 장도 안 떴다
2. 진행도 계기판이 **한 달 전 백업**을 읽고 있었다
3. 등록기가 176건을 «이미 있는 제품» 이라며 **기록 없이** 버렸다
4. 안전 검증기가 반려한 31건 중 절반이 **판정기 결함**이었다(`꿀` 이 성분이 아니라고 판정)
5. 고민 추론 힌트가 **영어뿐**이라 국내 제품 108건이 어떤 시나리오에도 안 잡혔다
6. 갱신이 **0행을 바꾸고도 «2건 바꿨다»** 고 보고했다(`.eq(칼럼, null)` 은 NULL 을 못 잡는다)

그래서 지금 도구들은 **버린 것도 기록하고, 왜 버렸는지 말하고, 실제로 바뀐 행만
센다.** 숫자가 안 움직이면 **도구가 고장 났을 가능성을 먼저 의심한다.**
