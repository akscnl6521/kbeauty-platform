## 1. 레퍼런스 이미지 → 얼굴 일관성

**Runway** — Gen-4의 핵심 마케팅 포인트가 캐릭터 일관성이다. 레퍼런스 1장으로
얼굴·의상·체형을 여러 생성에 걸쳐 유지한다고 설명한다. 다만 이 서술은 [2차]
출처이고, 공식 문서에서 레퍼런스 파라미터 상세 페이지는 404였다.

**Veo 3.1** — 「Ingredients to video」로 **레퍼런스 최대 3장** 지원. 구글
개발자 블로그 [공식]는 *"helps maintain character consistency"* 라고 쓴다.
«보장»이 아니라 «도움»이라는 표현을 그대로 쓴 점은 기록해 둔다.

**Kling** — multi-image-to-video 기능이 존재한다는 서술은 있으나 [2차],
공식 API 문서가 **HTTP 446으로 차단**되어 파라미터·제약을 확인하지 못했다.

> 우리 레퍼런스는 9장인데 Veo는 호출당 3장 상한이다. 우리 자체 규칙도
> «프레임당 최소 3장 대조»이므로 실무상 문제는 없고, 샷 각도별로 가까운 3장을
> 고르면 된다.

## 2. 프로그래밍 호출

**Runway** [공식] — 비동기. 생성 요청 → `{"id": "..."}` 반환 →
`GET /v1/tasks/{id}` 폴링 → `SUCCEEDED` 시 `output[0]`에 결과 URL.
권장 폴링 5초 이상, 지터·지수 백오프 권고. **공식 SDK가 Node(`@runwayml/sdk`,
TypeScript 바인딩 포함)와 Python 양쪽에 있고 `waitForTaskOutput()`으로 폴링을
감싸준다.**

**Veo** [공식] — 비동기. `generate_videos()`가 operation 객체를 반환하고
완료까지 폴링. Gemini API / AI Studio / Vertex AI에서 접근.

**Kling** [2차] — 비동기 태스크 + 폴링. 인증이 **정적 API 키가 아니라 JWT
서명**이다. AK/SK로 토큰을 만들어 요청마다 Bearer로 넣고, 토큰은 30분 만료.
셋 중 통합 부담이 가장 크다.

## 3. 비용 (1편당 개략)

튜토리얼 1편을 **30초**로 잡으면, 어느 서비스든 8~10초 상한 때문에
**3~4클립을 이어 붙여야** 한다.

**$15 내외**. 실패 재생성이 많은 초기에는 이보다 늘 수 있다.

## 4. 우리 검증 로직과의 통합

셋 다 «비동기 태스크 → 폴링 → 결과 URL» 구조라 통합 난이도는 비슷하다.
차이는 SDK뿐이고, 우리 스택이 TypeScript/Node라 **Runway 공식 Node SDK가
가장 손이 덜 간다.**

**단, 어느 쪽을 고르든 공통으로 막히는 지점이 있다:**

| 필요한 것 | 어느 API도 안 해줌 |
|---|---|
| 15~30초 만들기 | 클립 3~4개 **이어 붙이기** |
| 얼굴 검증용 정지 프레임 | 영상에서 **프레임 추출** |
| 「AI 생성 콘텐츠」 상시 표기 | **오버레이 굽기** |
| 마무리 안내 문구 | **자막 삽입** |

전부 **ffmpeg**이 필요하다. 현재 미설치이고, 서비스 키와는 **별개의 준비물**이다.

## 추천: **Runway (Gen-4 Turbo 초안 → Gen-4.5 최종)**

1. **필요한 기능이 그 제품의 주력이다.** 우리 요구의 핵심은 여러 클립에 걸친
   얼굴 동일성인데, Gen-4는 그걸 전면에 내세운 모델이다.
2. **스택이 맞는다.** 공식 Node/TS SDK + `waitForTaskOutput()`로 폴링까지
   감싸 준다. 우리 `check-model-identity` 하네스에 바로 물린다.
3. **1클립 10초로 가장 길다.** 30초 기준 이음매가 3개 → 2개로 준다.
   이음매마다 얼굴이 튈 위험이 있으므로 적을수록 좋다.
4. **가격을 공식 문서로 확인했다.** Kling은 공식 문서 접근 자체가 막혀
   숫자를 검증하지 못했다 — 계약 대상으로 삼기엔 확인되지 않은 항목이 많다.

**차점: Veo 3.1 Lite/Fast.** 레퍼런스 3장이 공식 문서로 확인되고 단가도 같은
급이다. **네이티브 오디오가 필요하면 Veo가 낫지만**, 우리는 한국어 자막·나레이션을
직접 얹을 것이므로 그 장점이 크지 않고, 오디오 티어는 4배 비싸다.

**Kling 보류 사유**: 기능 자체는 경쟁력이 있어 보이나 공식 문서가 차단되어
파라미터·제약·정확한 단가를 확인하지 못했고, JWT 서명 인증으로 통합 부담이 가장
크다. 확인 없이 계약을 권하지 않는다.

### 착수 시 필요한 것

1. Runway 개발자 계정 + API 키 (크레딧 선구매)
2. **ffmpeg 설치** — 키만으로는 시리즈를 못 만든다
