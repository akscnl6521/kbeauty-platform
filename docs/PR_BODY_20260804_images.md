## 1. 제품 이미지 — 한 번도 뜬 적이 없었다

사용자 지적 «이미지가 안 보인다» 를 확인해 보니, 이미지는 **처음부터 뜬 적이 없었다.**
부품은 다 있는데 **연결이 없었다:**

| 부품 | 상태 |
|---|---|
| `catalog_product_media` 테이블 | 있음 — Production 에는 **없었다** |
| `resolveVerifiedProductImageUrls()` | 있음 |
| `/api/catalog/product-images` 라우트 | 있음 |
| 카드의 이미지 렌더 코드 | 있음 |
| **라우트 → 카드 연결** | **없음 — 아무도 이 API 를 부르지 않았다** |

### 한 것

- **데이터** — 브랜드 Shopify 스토어의 `/products.json` 이 `images[].src` 로 공식
  제품 사진을 공개한다. 제품명 대조로 짝지어 **58건** 수집.
  **추천 풀 17건 전부** 포함.
- **테이블** — `catalog_product_media` 마이그레이션 (사람이 대시보드에서 실행 완료).
  원본에서 Staging 전용 테이블로 가는 외래키를 뺐다 — Production 에 없으면
  마이그레이션이 통째로 실패한다.
- **배선** — `useProductImages` 훅. 이미지 URL 은 **서명이 붙어 만료되므로**
  랭킹 캐시에 넣으면 안 되고 화면을 열 때마다 받아야 한다.

### 지어내지 않는다

- 제품명 대조 **0.8 미만이면 안 붙인다.** 엉뚱한 제품 사진은 사진이 없는 것보다
  나쁘다 — 사용자가 다른 제품을 산다.
- 이미지 URL 이 실제로 열리는지 **HEAD 로 확인**한다(HTTP 200 + `content-type: image/*`).
  죽은 링크를 저장하면 화면이 깨진 채로 남는다.
- 실패해도 화면을 막지 않는다. 카드에는 이미 «이미지 없음» 자리표시가 있다.

### 검증

```
catalog_product_media    0행 → 58행
추천 풀 이미지 해석      17 / 17   전부 성공
```

화면이 쓰는 것과 **같은 함수**(`resolveVerifiedProductImageUrls`)를 추천 풀 id 로
직접 태워 확인했다.

## 2. 검증기가 화면보다 후했다

`check:production-recommendations` 가 «구매 가능» 을 `retailer_country` ·
`verification_status` · `stock_status` **세 가지로만** 판정했다. 진짜 관문
(`isOfferPurchasableForCta`)은 여덟 가지를 본다 — 통화 일치, `ships_to_countries`
포함, `retailer_country` 일치 등.

**검증기가 화면보다 후하면 «검증 통과» 가 거짓말이 된다.** 실제 관문을 쓰도록 고쳤다.
결과 숫자는 같았지만(국내 13 · 미국 15) 우연히 맞은 것이었다.

## 3. 캐시 무효화를 CI 가 강제한다

«offer 로직을 바꾸면 캐시 버전을 올려라» 가 **주석으로만** 있었다. 주석은 잊는다.
그래서 배포하고도 화면이 안 바뀌는 사고가 났다.

`main` 대비 캐시 영향 파일 13개 중 하나라도 바뀌었는데 버전을 안 올리면 **CI 가 실패**한다.
배포 시점의 실제 변경 파일로 태워 이 관문이 그 사고를 «차단» 하는 것을 확인했다.

감시 범위는 **넓게** 잡았다 — 헛detection 의 대가는 «버전 한 번 더 올리기» 이고,
놓쳤을 때는 «배포해도 화면이 안 바뀜» 이다. 비대칭이다.

## 4. 성분 조회 — 슬래시 동의어

화장품 성분표의 슬래시는 두 가지로 쓰인다:

```
동의어   FRAGRANCE / PARFUM        ← 공백을 두른 슬래시
화학명   Caprylic/Capric Triglyceride
```

동의어면 조각 **하나만** 사전에 있어도 같은 성분인데, 전에는 «조각 전부 일치» 만
인정해서 `fragrance` 가 사전에 있는데도 미매칭으로 남았다.

식약처 사전 보강을 시도했더니 **78종 확인 → 실제 추가 2행**이었다. 즉 76종은 이미
사전에 있었고 **조회가 못 찾고 있었다.** 데이터가 아니라 매칭 문제였다.

## 알려진 한계 (문서에 근거와 함께 기록)

- **네이버 쇼핑 API 폐지** — 설정 문제가 아니다. `k뷰티매치` 앱에 검색이 이미
  등록돼 있고 블로그·뉴스·백과사전은 200 인데 `search/shop.json` 만 404 SE05 다.
  권한 문제면 401/403 이 온다. 국내 오퍼 추가 수집 경로가 없다.
- **카탈로그 확대는 막혀 있다** — 추천 풀 17건. 전성분 39/191 · 오퍼 38/191 이
  병목이고, 국내 소스는 쿠팡·올리브영 403, 나머지는 JS 렌더링이다.
- **규제 성분 판정은 식약처 데이터로 불가** — 금지 조건이 성분명 안에 박혀 있고
  한국을 금지국으로 다는 행이 47%다. 거짓 경보를 낼 뻔한 것을 보고 전에 막았다.
