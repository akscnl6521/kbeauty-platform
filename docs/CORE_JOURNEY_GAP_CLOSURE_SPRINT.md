# Core Journey Gap Closure Sprint

최종 갱신: 2026-07-19
기준 문서: K-Beauty Match Master Plan v4.1
작업 브랜치: `docs/master-plan-v4.1-20260718`

## 1. 목적

현재 구현된 피부 분석, 추천, Top 5, 루틴, Continuous Care 기반을 하나의 완결된 사용자 여정으로 연결한다.

이번 스프린트에서는 제품 영상, 피부과 데이터베이스, 제휴·광고, 자동 갱신 프레임워크를 구현하지 않는다. 해당 기능은 핵심 사용자 여정이 닫힌 뒤 순서대로 진행한다.

## 2. 목표 사용자 여정

```text
문진 시작
→ 부위·증상·심각도·발생 기간 입력
→ 위험 신호 확인
→ 화장품 관리 가능 범위 판정
→ 추천 성분·주의 성분
→ 실제 구매 가능 제품 Top 5
→ 추천 이유·추천하지 않는 이유
→ 아침·저녁 루틴
→ 결과 저장
→ 3일 체크인 예약
→ /my에서 이전 결과와 다음 행동 확인
```

## 3. 이번 스프린트 구현 범위

### A. 분석 입력 확장

기존 단순 고민 선택을 다음 구조로 확장한다.

- 부위
- 증상
- 심각도
- 발생 기간
- 악화 여부
- 통증·출혈·진물·급격한 부기 등 위험 신호
- 현재 사용 제품과 최근 반응

최초 분석은 2~3분 안에 완료할 수 있도록 기본 질문과 추가 질문을 분리한다.

### B. 관리 단계 판정

분석 결과에 다음 상태를 명시한다.

- A: 화장품 중심 관리 가능
- B: 화장품 사용 후 경과 관찰
- C: 화장품 관리와 전문가 상담 병행
- D: 피부과 또는 전문가 상담 우선
- E: 신속한 의료기관 확인 권장

위험 신호가 있으면 제품 추천과 구매 링크를 제한한다.

### C. 추천 결과 완성

결과 화면에는 다음을 표시한다.

- 관리 단계
- 화장품으로 기대 가능한 범위
- 화장품의 한계
- 추천 성분
- 주의·회피 성분
- Organic Top 5
- 추천 이유
- 추천하지 않는 이유
- 데이터 신뢰도
- 정보 부족 상태
- 제품이 없을 때 억지 추천하지 않는 빈 결과

### D. 루틴 연결

- 아침 루틴
- 저녁 루틴
- 주간 루틴
- 사용 순서
- 새 제품 도입 순서
- 자극 발생 시 중단 안내
- 현재 제품 중복·과다 사용 안내

### E. 결과 저장과 Continuous Care 연결

- 분석 결과 저장
- 관리 단계 저장
- 선택한 제품과 루틴 저장
- 체크인 동의 확인
- 3일 체크인 예약
- 이후 7일·15일·30일 일정 생성
- `/my`에서 다음 체크인 날짜와 현재 루틴 표시

### F. 체크인 분기

다음 응답을 지원한다.

- 좋아짐 → 현재 루틴 유지
- 변화 없음 → 사용법·기간·기대 범위 확인
- 악화 → 제품 중단 검토·루틴 단순화·상담 분기
- 사용하지 않음 → 이유 확인·시작일 재설정
- 잘 모르겠음 → 간단 비교 또는 사진 기록 안내

응답하지 않으면 48시간 후 한 번만 재알림하고 추가 반복은 중단한다.

## 4. 수정 후보 영역

실제 파일 경로는 코드 분석 후 확정한다.

- 분석 질문 및 분석 상태 타입
- `/api/analyze`
- 추천 결과 타입과 결과 페이지
- 안전 필터와 상담 분기
- 루틴 생성 로직
- 결과 저장 API
- `/api/care/*`
- `/my`
- worker의 follow-up 예약 처리
- i18n 번역 키
- journey·smoke·quality 테스트

## 5. 수정하지 않을 영역

- Production 배포
- Production DB write
- Production 환경변수
- main 직접 수정
- 제품 자동 최종 승인 정책
- 병원 추천 데이터베이스
- 제휴·광고 정렬
- 제품 사용 영상
- 대규모 카탈로그 재수집

## 6. 완료 조건

다음 조건을 모두 충족해야 완료로 본다.

1. 분석에서 부위·증상·심각도·기간을 저장한다.
2. 위험 신호 입력 시 D 또는 E 단계로 분기한다.
3. 위험 신호 결과에서 구매 링크가 제한된다.
4. 제품이 없거나 데이터가 부족하면 빈 결과를 정상 표시한다.
5. 추천 이유와 추천하지 않는 이유가 함께 표시된다.
6. 아침·저녁 루틴이 결과에 연결된다.
7. 결과 저장 후 3일·7일·15일·30일 체크인 일정이 생성된다.
8. `/my`에서 이전 분석, 현재 루틴, 다음 행동을 볼 수 있다.
9. 악화 응답이 루틴 단순화 또는 상담 우선으로 분기된다.
10. 기존 추천·관리자·카탈로그 기능이 회귀하지 않는다.

## 7. 테스트 기준

```text
npm run test:pipeline
npm run test:journey
npm run test:smoke
npm run test:quality
npm run check:responsive
npm run build
```

추가 E2E 시나리오:

1. 가벼운 건조 → A 또는 B → 제품 Top 5 → 루틴 → 체크인 생성
2. 반복되는 심한 염증성 여드름 → C 또는 D → 상담 우선 설명
3. 통증·출혈·진물 → E → 제품·구매 링크 제한
4. 공식 검증 제품 없음 → 정보 부족 결과, 가짜 제품 없음
5. 3일 체크인 악화 응답 → 중단 검토·상담 분기

## 8. 실행 순서

```text
현재 코드와 타입 분석
→ 기존 사용자 여정 지도 작성
→ 분석 입력 최소 확장
→ 관리 단계 판정
→ 결과 UI 연결
→ 결과 저장·체크인 연결
→ /my 연결
→ E2E와 회귀 테스트
→ Preview 검증
→ 작업 브랜치 commit·push
```

## 9. 승인 경계

작업 브랜치, Staging, 테스트, Preview는 기존 승인 정책에 따라 진행한다.

다음은 별도 명시 승인 전 실행하지 않는다.

- main 병합
- Production 배포
- Production DB write
- Production 환경변수 변경
- 파괴적 SQL
